PROBLEM

搜索解决不了的问题，不是“再搜一次”

精确匹配、文档孤岛、反复改词——这三件事叠在一起，用户最后只能去问客服。

01

精确匹配，容错极差

搜「小红书」有结果，搜「小书」就没有。错别字、别名、口语全部落在召回之外。

query: 小书怎么发 → 0 results
02

帮助文档是孤岛

功能说明、FAQ、版本差异散落在文档里，站内搜索搜不到，用户只能转客服。

docs: 54 节 · 可被搜到: 未知
03

一次检索解决不了

同一个问题要换 3–5 次关键词。用户要的不是更多结果，而是一个能执行的答案。

attempts: 3.4 次 / 问题

RAG 不是加一个聊天框，而是把 检索、回答、引用、拒答、评测 连成一条可验证的链路。

PIPELINE

一条链路，九个环节

每个环节都可替换：换模型、换召回、换重排，不影响其他部分。

1解析HTML / PDF
2切片按 §章.节
3Embedding4096 维
4索引54 chunks
5混合召回向量 + BM25
6Reranktop 12 → 5
7Prompt只依据资料
8引用[n] + 原文链接
9评测Recall / 拒答
关键设计：原始问题与改写问题各召回一次、各 rerank 一次，取较高分，避免改写跑偏时误伤正确文档。

FIELD NOTE

一个只在批量 > 8 时才出现的坑

SiliconFlow embeddings 接口单批超过 8 条时，返回的 index 会每 8 条重置一次。

返回的 index
// 传入 16 条，期望 0..15
[0,1,2,3,4,5,6,7, 0,1,2,3,4,5,6,7]

// 若按 index 排序，第二批向量整体错位
// 现象：明明有正确文档，却召回不到

修复

不按 index 排序，按响应顺序与输入顺序对齐，并校验返回条数。

if (r.data.length !== batch.length) throw ...
for (const d of r.data) vectors.push(d.embedding);

这个 bug 很隐蔽：单条、8 条以内批量都正常，只有超过 8 条才出现。

REPOSITORY & CLI

一条命令复跑，或者把它做成产品

无运行时依赖，只需要 Node 22+ 和一个 SiliconFlow Key。

终端
$ npm install
$ npm run index
$ npm run demo -- "怎么导出报表"
$ npm run eval -- 12
$ npm start
# → http://127.0.0.1:3000
